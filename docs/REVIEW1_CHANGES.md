# Changes made against faculty Review 1

The project now has completed implementation fixes, a repeatable research evaluation path, an isolated four-condition study interface and explicit evidence limits. These changes address the software and experiment infrastructure portions of the faculty review. They do not turn synthetic data into independent findings or complete a human-subject study.

Source: `/Users/arshnarula/Downloads/Review 1.docx`, assessment dated 10 November 2026. The full text, tables and equations were read; no embedded comments, footnotes, endnotes or images were present. The source review and existing Word results document were not modified. Existing uncommitted changes and historical result files were retained.

## Itemized implementation changes

1. **Mandatory encrypted personal profiles** (`vault/store.py`). Removed the optional plaintext-write path. A missing DEK now raises an authentication error. Reading a legacy profile while locked returns nothing; reading after unlock migrates it to encryption. Migration errors are no longer silently suppressed. Enabled SQLite secure-delete for future deletions/updates, without claiming historical forensic erasure.
2. **Encrypted profile backup preservation** (`vault/backup.py`). Backups now include encrypted profile metadata and reject unmigrated plaintext metadata. Backup files receive owner-only permissions.
3. **Validated, atomic restore** (`vault/backup.py`, Import/Export page). Check backup record structure, duplicate IDs and declared counts. In the application, verify the backup master password and every encrypted entry/profile before replacing storage in one transaction. Avoid mixing records encrypted under different keys. Lock the session after restore. Tampered restore failures leave the previous vault usable.
4. **Explicit breach uncertainty** (`vault/audit.py`). Replace the invented 0.5 “unknown breach risk” with `None` and an explicit unknown status. Preserve failed lookup count as -1. Compute lower/upper heuristic risk and vault-health bounds from the two possible breach endpoints.
5. **Honest unknown-state UI** (Security Audit page). Show incomplete-assessment warnings and a health interval; suppress a confident grade when breach evidence is unavailable. Explain that heuristic scores are not compromise probabilities.
6. **Age handling** (`vault/audit.py`, Settings/Audit pages). Honor the age opt-out even when custom weights are nonzero. Retain age as descriptive information and optional policy/research input; remove default stale-password security warnings. Use configuration-specific rotation days.
7. **Reproducible live model defaults** (`vault/audit.py`). Disable implicit loading of any file named `data/calibrated_scorer.json`. Loading is explicit, validates finite coefficients/features, and fails clearly for an invalid configured model. Research fits remain outside live defaults.
8. **Shared risk calculation** (`vault/audit.py`, `vault/research.py`). Audit and research use the same current fixed-weight helper. Preserve the submitted six-signal weights as a separately named baseline. Correlation capping is documented as a heuristic, not a calibrated correction.
9. **Same-service reuse detection** (`vault/audit.py`). Exclude the current entry by ID, not site name, so two accounts at the same service still count as reuse.
10. **Derivative consistency and memory** (`vault/audit.py`, `vault/gate.py`). Save gate and audit share the direct pair rule. Replace the n² adjacency matrix with streaming comparisons, use iterative Union-Find path compression, validate mode names and stabilize greedy pairwise grouping by entry ID. Preserve explicit chain semantics and document their transitive-link limitation.
11. **Personal-year false-match fix** (`modules/semantic.py`). A detected name no longer makes the detector report a two-digit birth year that is absent from the password. Removed duplicate normalization definitions.
12. **Breach response validation** (`modules/syntactic.py`). Validate the allowed endpoint before sending, disable redirects, require a successful status and valid suffix/count rows, and preserve unknown status for empty/malformed responses. Keep padded five-character prefix queries.
13. **Local credential suggestions** (`modules/llm.py`). Remove the remote generation path even when an API key exists. Suggestions use the local CSPRNG. Remove blanket entropy guarantees from fallback prose.
14. **Remove unsupported security claims** (`vault/gate.py`). Replace “un-crackable” and “zero reuse risk” copy with qualified generation descriptions. No generated password is presented as proof against compromise.
15. **Session cleanup** (`vault/session.py`). Locking clears plaintext widget values, pending credential objects, generated values and cached reports in addition to the mutable DEK. Recovery attempts now participate in login throttling.
16. **Credential workflow fixes** (Vault page). Remove the incomplete embedded study branches, keep research separate, repair generated-password filling, invalidate stale audit results after vault interactions, and preserve creation dates/history when editing credentials. Record modification time for password changes and initialize edit timing.
17. **Remove inactive settings controls** (Settings page). Replace sliders that claimed to normalize weights but never applied them with an accurate read-only display of deployed weights and research configuration guidance.

## Experiment and research changes

18. **E1 dataset interface and smoke generator** (`scripts/review_experiments.py`). Add explicit personal labels, independent attack outcomes, provenance, categories, train/validation/test partitions and group IDs. Run 11,022 synthetic examples across 1,002 profiles; reject cross-partition user, family, template and exact-password leakage. This is an engineering fixture, not independent validation.
19. **E1 metrics and errors**. Export confusion counts, precision, recall, F1, FPR, balanced accuracy, PR-AUC/ROC-AUC, category results and held-out predictions. Freeze thresholds using validation, rather than test outcomes.
20. **E2 matched comparisons**. Evaluate B1–B7 and current CAV against the same S5 outcome. Distinguish synthetic breach fixtures from HIBP evidence and the submitted model from current production scoring.
21. **E2 ablation and calibration**. Add all six feature removals with unchanged fixed weights and separately refitted logistic models, criticality aggregation analysis, Brier scores, observed risk bands, validation-constrained FPR thresholds and profile-level paired bootstrap recall-difference intervals. Export research-only coefficients with provenance.
22. **E3 five attacker scenarios** (`vault/research.py`). Implement bounded, distinct, ordered guesses for general knowledge, personal information, history and both combinations. Candidate generation never sees the target. Record rank and actual guess count. Execute 100- and 1,000-guess runs; support larger requested budgets while reporting finite-stream exhaustion.
23. **Derivative evaluation** (`scripts/review_clusters.py`). Add independent planted family definitions, pairwise metrics, adjusted Rand index, B-cubed metrics and history-mutation recovery for chain and pairwise grouping.
24. **E4 isolated study page** (`pages/7_Controlled_Study.py`, `app.py`). Add G1 conventional, G2 post-save, G3 pre-save and G4 pre-save-plus-alternative workflows using fictional tasks and temporary session storage. Preserve G2 warnings until a decision, offer editing, and record total decision time. No study credential enters the real vault.
25. **E4 consent and provenance** (`vault/study.py`). Require participant consent in the UI. Human mode requires configured ethics reference and allocation seed. Mark demo/synthetic/human sources explicitly. Remove stored password hashes entirely; log independent vulnerability outcomes and pseudonymous task metadata.
26. **E4 analysis** (`scripts/export_study_logs.py`). Add participant-level estimates, clustered bootstrap intervals, timing/adoption/override summaries and timing/alternative contrasts. Reject duplicate participant-task records, inconsistent assignment and legacy logs without provenance/outcomes. No human results were manufactured.
27. **Protect historical results from simulations**. The pilot simulator writes to `results/synthetic_pilot.csv` with synthetic provenance instead of `results.csv`. Legacy pilot analysis refuses unsupported human provenance. Older E1–E3/performance scripts now warn that they are superseded exploratory harnesses.
28. **E5 security validation**. Add regression tests for profile write enforcement, backup profile preservation and atomic tamper rejection, unknown breach intervals, malformed responses, session plaintext cleanup, same-service reuse and absent birth-year matches. Document the review's ten security scenarios and unresolved boundaries in `SECURITY_MATRIX.md`.
29. **E6 actual local computation** (`scripts/review_performance.py`). Benchmark real syntax/semantic work, save gate, derivative clustering and component removals at every requested size through 5,000 entries. Export raw times, median/p95/p99, traced Python memory and host metadata. Explicitly exclude mocked HIBP latency. Execute the existing Argon2 configuration benchmark and retain its output.
30. **Deterministic tests and UI checks**. Isolate network and clipboard fixtures so tests neither leak test inputs nor overwrite the user's clipboard. Exercise every study condition and the real vault's warn-before-save/override behavior using Streamlit AppTest.
31. **Reproducible environment and commands**. Create a local `.venv`, record tested dependencies in `requirements-lock.txt`, ignore the environment, and add a README plus experiment protocol. Preserve separate new results under `results/review1/`.
32. **Evidence-bounded research revision** (`RESEARCH_REVISION.md`). Provide revised title, abstract, gap, research questions, prior-work comparison, threat model, architecture distinction, methodology, discussion and conclusion. Verify core references against publisher/author/standards sources. Document negative results and avoid unsupported novelty, safety, behavioral or journal-readiness claims.
